1. EXECUTIVE SUMMARY
--------------------------------------------------------------------------------
This project implements a complete lifelong MAPF simulation system with 
disruption injection, incident detection, deterministic plan validation, multi-agent
solvers (PIBT, LNS, Windowed PBS), and a high-performance browser 3D replay viewer
built with Vite, TypeScript, and Three.js.

Both foundational tracks (Part A: 3D Replay Viewer, and Part B: Python Simulation
Pipeline) are actively implemented and tested.

4. PART A — BROWSER 3D REPLAY VIEWER (STEPS 1 - 5)
--------------------------------------------------------------------------------
Built in `viewer/` using Vite + TypeScript + Three.js.
Local dev server live at: http://127.0.0.1:5173/

- 3D Warehouse Scene & Lighting:
  * MovingAI .map parser converting grid cells to 3D world coordinates:
    cell (x, y) -> world (x + 0.5, 0, y + 0.5).
  * Concrete floor with repeat texture wrapping and subtle aisle guidance lane lines.
  * All warehouse shelves rendered via a single instanced mesh (InstancedMesh)
    casting soft shadows.
  * DirectionalLight with 2048x2048 soft shadow map fitted to map bounds.
  * Equirectangular reflection environment mapping using warehouse.hdr.
  * ACESFilmicToneMapping (exposure 1.15), flat dark background, zero AmbientLight.
- Robot Animation & Status Lighting:
  * 100 robots rendered with InstancedMesh and blurred floor shadow decals.
  * Ease-in-out interpolation between frames.
  * Turn-before-move rotation: robots turn in the first 33% of the step, then translate.
  * Dynamic per-instance emissive LED colors based on robot state:
    - Moving: Light Blue (#38bdf8)
    - Idle: Green (#10b981)
    - Delayed: Amber pulsing at 1 Hz (#f59e0b)
    - Failed: Off (#1e293b) with red chassis tint (#ef4444)
    - Replanning: Magenta pulsing at 2 Hz (#d946ef)
- Disruption & Path Visualizations:
  * Dynamic barrier cones and red translucent floor tiles on blocked cells.
  * Grey ring decals under failed robots.
  * Invalidated paths rendered as dashed red fat lines (Line2).
  * Repaired paths rendered as solid light blue fat lines smoothed via Catmull-Rom curves.
  * Faint floor rectangles showing congestion regions colored by level (low/medium/high).
  * Dashed magenta lines linking interacting incidents.
  * Automatic dimming of non-affected robots to 60% when an incident is selected.
- Interactive HUD & Timeline:
  * Top-left Metrics Tiles: Repair Success %, Mean Recovery Steps, Path Cost Delta %,
    LLM Calls vs Cache Hits.
  * Baseline Toggle: Instant switch between LLM-guided replay and Baseline PIBT
    without losing current step position.
  * Top-right Live FPS Counter (60 FPS on integrated GPU).
  * Scrubbable step slider with color-coded incident ticks (blocked red, failure grey,
    delay amber).
  * Playback controls: Play/Pause, 0.5x / 1x / 4x speed selectors, Prev/Next incident
    buttons and keyboard shortcuts ('N' and 'P').
  * Collapsible Right Incident Panel: Displays Sentinel, Cache, Dry-run, LLM directive,
    Solver badge, and Validator verification attempts.
  * Camera Presets:
    - Key 1: Whole map overview
    - Key 2: 45-degree aisle view
    - Key 3: Follow selected robot (click robot to select)
    - Smooth 1-second camera lerp between presets
    - Smooth 4-second intro dolly on initial page load

5. PART B — PYTHON RESEARCH PIPELINE (STAGES 1, 2, 3, 7, 8)
--------------------------------------------------------------------------------
Package: `amr_repair/`

- Stage 1: Lifelong MAPF Simulator
  * amr_repair/sim/grid.py: GridMap class loading MovingAI .map files into NumPy
    boolean arrays and 4-connected NetworkX graphs.
  * amr_repair/sim/agents.py: Robot dataclass tracking id, pos, goal, path, state.
  * amr_repair/sim/lifelong.py: World class advancing simulation step-by-step,
    assigning lifelong random goals upon arrival, and recording frame history.
  * Unit tests: tests/test_stage1.py (all passed).

- Stage 2: Disruption Injector
  * amr_repair/disrupt/injector.py: Injector class supporting blocked cells, robot
    failures, and delays with duration/unblocking.
  * Supports overlap modes ('none', 'same_robot', 'same_aisle') to guarantee
    interacting multi-robot disruptions.
  * Unit tests: tests/test_stage2.py (all passed).

- Stage 3: Sentinel Incident Detection
  * amr_repair/sentinel/incident.py: IncidentRecord Pydantic model and 12-dimensional
    normalized feature vector extractor (`features()`) for caching.
  * amr_repair/sentinel/detect.py: IncidentDetector identifying affected robots whose
    planned paths intersect disruption cells, computing padded congestion regions,
    calculating density, and merging interacting incidents with `interacts_with`.
  * Unit tests: tests/test_stage3.py (all passed).

- Stages 7 & 8: Solvers and Deterministic Validator
  * amr_repair/validate/validator.py: Pure deterministic ground-truth validator.
    Checks in order:
    1. Static blocked cells
    2. Failed robot cells
    3. Vertex collisions
    4. Edge swap collisions
    5. Deadlocks (10 consecutive steps stationary while not at goal)
  * Solvers (shared signature: `solve(world, robots, priority, horizon)`):
    - amr_repair/solvers/pibt.py: Priority Inheritance with Backtracking.
    - amr_repair/solvers/space_time_astar.py: Space-Time A* search with vertex/edge
      reservations.
    - amr_repair/solvers/lns.py: Large Neighborhood Search destroying 3-5 robot
      neighborhoods and repairing with Space-Time A*.
    - amr_repair/solvers/windowed_pbs.py: Windowed Priority-Based Search exploring
      priority orderings with 500ms timeout guarding.
  * Unit tests: tests/test_stages7_8.py (all passed).
